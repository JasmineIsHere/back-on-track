## [BOT-001] Create useLocalStorage Custom Hook

**Status:** [x] Done
**Priority:** High
**Feature Area:** Infrastructure

### Description
The README specifies persistence via a custom `useLocalStorage` hook, and multiple features (habit list, streaks, mood check-in) depend on it. The `src/hooks/` directory does not exist yet. This hook must be created before any persistence feature can be built.

### Acceptance Criteria
- [ ] `src/hooks/useLocalStorage.js` exists and exports a `useLocalStorage(key, initialValue)` hook
- [ ] Hook returns `[value, setValue]` identical in shape to `useState`
- [ ] On first call with a new key, `initialValue` is written to localStorage and returned
- [ ] On subsequent calls with the same key, the stored value is read from localStorage and returned
- [ ] Calling `setValue` updates both the React state and localStorage atomically
- [ ] If localStorage contains invalid JSON for the key, the hook falls back to `initialValue` without throwing

### Technical Notes
- Lives in `src/hooks/useLocalStorage.js` — create the `src/hooks/` directory
- No styled components involved — this is a pure logic hook
- Use `JSON.stringify` / `JSON.parse` for serialization so arrays and objects work correctly
- Do not call `localStorage.getItem` / `localStorage.setItem` directly in any component — this hook is the only permitted access point per CLAUDE.md guardrails

### Dependencies
- None

## [BOT-003] Create AppContext for Cross-Page Shared State

**Status:** [ ] Open
**Priority:** High
**Feature Area:** Infrastructure

### Description
The Home Dashboard needs to read habit completion percentage and flashcard progress — data that lives in other pages. Since state is currently local to each page via `useState`, the Dashboard cannot access it. AppContext lifts the habits list and flashcard progress into a shared context so any page can read it. This also enables the streak tracking that depends on persisted habit history.

### Acceptance Criteria
- [ ] `src/context/AppContext.jsx` exists and exports an `AppProvider` component and a `useAppContext` hook
- [ ] `AppProvider` wraps the app in `App.jsx` (inside `ThemeProvider`, outside `BrowserRouter`)
- [ ] Context provides: `habits` (array), `setHabits` (function), `flashcardProgress` (object with `completed` and `total` counts), `setFlashcardProgress` (function)
- [ ] `habits` is initialised from `useLocalStorage` so it persists across page refreshes
- [ ] `HabitsPage` reads and writes `habits` / `setHabits` from context instead of local `useState`
- [ ] Calling `useAppContext` outside an `AppProvider` throws a descriptive error

### Technical Notes
- Lives in `src/context/AppContext.jsx` — create the `src/context/` directory
- Uses `useLocalStorage` from `src/hooks/useLocalStorage.js` (BOT-001 must be done first)
- Follow CLAUDE.md state management pattern: cross-page state in context, local UI state stays in `useState`
- `App.jsx` must import `AppProvider` and wrap the tree; no other file in the routing tree needs to change at this stage
- No styled components in this file

### Dependencies
- BOT-001 (useLocalStorage hook required for persistence)

- Use theme tokens from `src/theme.js` — no hardcoded hex values

## [BOT-005] Flashcard Flip-Card Interface, Self-Rating, and Queue

**Status:** [ ] Open
**Priority:** High
**Feature Area:** Flashcard Deck

### Description
The FlashcardsPage is currently a stub that only displays a topic in the header. The README specifies a full flip-card interface where users can see a question, flip the card to reveal the answer, rate themselves ("Got it" / "Review again"), and have struggling cards return to the queue automatically. A progress bar should track how many cards have been cleared. This ticket builds the complete flashcard study experience.

### Acceptance Criteria
- [ ] Cards load from `src/data/flashcards.js` (BOT-002 must be done first)
- [ ] One card is displayed at a time showing the question face-up
- [ ] Clicking/tapping the card flips it to reveal the answer (CSS flip animation or toggle)
- [ ] After flipping, two buttons appear: "Got it" and "Review again"
- [ ] "Got it" removes the card from the current queue and advances to the next card
- [ ] "Review again" sends the card to the back of the queue so it appears again later
- [ ] A progress bar shows `clearedCount / totalCards` as a percentage
- [ ] When all cards are cleared, a completion message is shown
- [ ] `flashcardProgress` in AppContext is updated whenever a card is cleared, so the Home Dashboard can read it

### Technical Notes
- `FlashcardsPage.jsx` manages the active queue via `useReducer` (actions: FLIP, RATE_GOT_IT, RATE_REVIEW_AGAIN, RESET)
- Styled components for the card, flip animation, rating buttons, and progress bar go in `src/pages/FlashcardsPage/index.js` — this file needs to be created (it doesn't exist yet)
- Flip animation: use a CSS `transform: rotateY(180deg)` transition on a styled component that receives a `$flipped` transient prop
- Use theme tokens for all colours — no hardcoded hex values
- Read flashcards data from `src/data/flashcards.js`; filter by `selectedTopic` if a topic is chosen

### Dependencies
- BOT-002 (static flashcard data)
- BOT-003 (AppContext — to update `flashcardProgress` for the Home Dashboard)
